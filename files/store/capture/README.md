# capture —— 抓包工作台

HTTP(S) 抓包代理 + **浏览器工作台**。零依赖（只用 Python 标准库），macOS / Linux 都能跑。

抓包结果直接落盘成 JSONL，**人和 AI 都能原生读取** —— 不需要导出、不需要 GUI、不需要系统授权。

## 给最终用户（不碰命令行）

**安装**（管理员做一次）：

```bash
bash install.sh
```

装完桌面上会出现 **「抓包工作台」**，**双击即可** —— 自动启动服务并打开浏览器。

**日常使用：全在浏览器里**

| 页签 | 内容 |
|---|---|
| **请求** | 抓到的请求列表，点开看完整请求/响应体，一键复制 JSON / cURL |
| **设备** | 谁连进来了、什么设备、怎么让新设备接入（分 Android / iOS 步骤） |
| **状态** | 服务是否在跑、代理地址、抓了多少条、抓不到时的排查顺序 |

### 当前 / 历史 两种模式

「请求」页左上角切换：

| 模式 | 显示什么 | 设备断开后 |
|---|---|---|
| **当前** | **只显示在线设备**的日志 | 该设备的日志**自动从视图消失**（数据不丢） |
| **历史** | **全部**抓包数据 | 仍可查看 |

**在线怎么判定：主动探测 + 服务端推送**

不是靠"最近有没有请求"猜，而是**主动 ping**，状态一变**立刻推**给浏览器：

```
服务端                                   浏览器
presence_loop 每 2s ping 一轮
    ├ 状态变化 → broadcast("presence") ──▶ SSE 立刻更新徽标
    │
抓到一个请求 → write_flow()
    └──────────── broadcast("flow") ─────▶ SSE 立刻插入列表
```

所以：

| 事件 | 延迟 |
|---|---|
| 手机发一个请求 | **立刻**出现在列表（服务端推送，不是轮询） |
| 手机断开 / 拔掉 | **≤2 秒**徽标变离线，「当前」模式日志当场清空 |

顶部有 **🟢 实时** 指示灯；连接断了会显示「重连中…」并自动重连。

| 状态 | 含义 |
|---|---|
| 🟢 在线 | ping 得通，设备在网络上 |
| ⚪️ 离线 | ping 不通，设备已断开 |
| ◌ 探测中 | 刚接入的头几秒还没轮到探测 |

> 探测间隔：`capture.py` 的 `presence_loop(interval=2.0)`
> 推送通道：`GET /api/events`（SSE）；前端 `EventSource` 订阅，另有 6 秒轮询兜底

设备下拉在两个模式下内容不同：

```
当前模式：[全部设备（1 台在线）▾]
          └ 🟢 🤖 Android · 40 条

历史模式：[全部设备（1 台在线）▾]
          ├ 🟢 🤖 Android · 40 条
          └ ⚪️ 🖥 本机 · 3 条      ← 离线设备也能选
```

> 点离线设备时会**自动切到历史模式**，否则会看到空列表。

### 监听哪台：点圆点，变绿才开始抓

「设备」页每台设备左边有个圆点。**灰色 = 侦测到了但没在监听，绿色 = 正在监听。**

```
⚪️ 本机（这台 Mac）        305 条      ← 灰：不抓
🟢 Android · Redmi …        40 条      ← 绿：正在抓，它的日志才会出现在「请求」里
⚪️ 未知来源（早期记录）      47 条
```

- **点一下圆点 = 开始/停止监听**，想听哪台就点绿哪台，多台可以同时绿
- 设备一被发现就列出来（拨号盘里所有同网段机器也在内），**默认全是灰的**
- 没点绿的设备，报文**照样原样落盘**，只是不进列表 —— 点绿的那一刻，它**过去的历史记录立刻就在了**，不是从零开始
- 所以"监听"是个**视图开关**，不是数据丢不丢的问题：随时改主意，不损失任何信息
- 状态记在 `config.json` 的 `monitored` 里，重启仍在；多个浏览器标签页之间同步（SSE 推送）

**「本机」比较特别**：点绿它等于把**这台 Mac 的系统代理**指到本工具（`cap local on`），点灰则还原。所以：

- 点绿本机后，浏览器 / 各 App 的流量都会进列表
- **代价：工作台一停，这台电脑就断网**（代理指向了一个已停的端口）。工具正常退出和下次启动都会自动还原/校正，但强杀进程时需要手动 `cap local off`
- 因此**默认不监听本机** —— 只在真要抓本机时才点绿

> 早于 `client` 字段那版的记录没有来源设备，无法归到任何一台，单独列成「未知来源」一项，点绿即可查看。

### 手机接入：扫二维码，不用手打 IP

「设备与状态」→「让手机连上这里」里有一个**二维码**：

```
┌──────────┐   手机扫这个码
│ ██▀▀██▀█ │   → 打开接入页，照着填代理
│ ██▄▄██▀█ │   → 地址、端口直接复制，不用手打
└──────────┘
http://192.168.0.104:8892/
```

扫码打开的是**手机接入页**（另一个端口，只读）：

| 端口 | 谁能访问 | 内容 |
|---|---|---|
| 8891 | **只有本机**（绑 `127.0.0.1`） | 完整工作台，能看到所有抓包数据 |
| 8892 | 局域网（绑 `0.0.0.0`） | **只有接入说明** —— 代理地址 + 分机型步骤，不含任何抓包数据 |

**为什么不直接把工作台开给手机**：那等于把抓到的报文给整个网段看。所以拆成两个端口，
手机能打开的只有一页静态说明。

接入页会显示主机名/端口 + 一键复制，并按 Android / iPhone 分别给步骤
（自动识别机型，也能手动切）。扫码 → 填代理 → 回电脑点那个设备**变绿**，就通了。

> 二维码是**页面内实时生成**的（纯 JS 编码器，零依赖），地址变了码就跟着变，不存在图片过期的问题。

### 按设备切日志

（下面这个下拉只影响**看**，不影响**抓** —— 抓谁由上面的绿点决定。）

「请求」页左上角有**设备下拉**，多台设备同时被监听时可以切换只看某一台：

```
[全部监听设备（2）▾]  [搜索____] [主机▾] [方法▾] [状态▾]
 ├ 全部监听设备（2）
 ├ 🟢 🤖 Android · Redmi 21091116C · 40 条
 └ 🟢 🖥 本机 · 305 条
```

- 选择会**记住**（下次打开还是这台）
- 切设备时详情面板会清空，避免看串
- 点设备**整行**= 在下拉里选中它；点**圆点**= 切换监听（两个动作分开，不会点错）

用户**不需要打开终端、不需要记任何命令**。

## Web 工作台

浏览器打开 `http://127.0.0.1:8891`（或 `cap open`）：

```
┌──────────────────────────────────────────────────────────────┐
│ capture   [搜索____] [主机▾] [方法▾] [状态▾] [☐杂音]  ⟳     │
├───────────────────────┬──────────────────────────────────────┤
│ 88   GET  200  17:02  │ GET /basic/users/getTime             │
│ /basic/users/getTime  │ 状态 200 · 耗时 195ms · 客户端 .225  │
│ ─────────────────     │ ────────────────────────────────     │
│ 29   GET  200  16:29  │ ▸ 请求头                             │
│ /basicConfig/query…   │ ▸ 请求体                             │
│ ─────────────────     │ ▸ 响应头                             │
│ …                     │ ▾ 响应体（JSON 自动美化）            │
└───────────────────────┴──────────────────────────────────────┘
```

功能：
- **实时刷新**（2 秒一次，可关）
- **过滤**：全文搜索、主机、方法、状态码
- **系统杂音默认折叠**，勾选可看全部
- **详情**：请求头/体、响应头/体，JSON 自动美化
- **一键复制 JSON / cURL**（方便贴给 AI 或同事复现）

工作台只读，且**只监听 127.0.0.1**（数据不出本机）。

## 命令

### 生命周期

| 命令 | 说明 |
|---|---|
| `cap start [--port N]` | 启动代理 + Web 工作台 |
| `cap stop` | 停止 |
| `cap open` | 浏览器打开工作台 |
| `cap status [--json]` | 状态、条数、手机该填什么 |
| `cap doctor [--json]` | 自检：环境/端口/进程/客户端/PATH，带修复建议 |
| `cap devices [--json]` | 识别接入的设备 + 扫局域网 + 给每个平台的接入步骤 |
| `cap scan [--subnet X] [--no-ping] [--json]` | 主动扫网段：谁在网络上、谁走了代理 |
| `cap config` | 查看配置 |
| `cap config set port 8891` | 改配置（`port` / `web_port` / `redact` / `noise`） |
| `cap clear` | 清空数据（旧文件自动备份） |

### 查询

| 命令 | 说明 |
|---|---|
| `cap list --last 20` | 最近 20 条 |
| `cap show 42` | 第 42 条的**完整**请求头/体 + 响应头/体 |
| `cap tail` | 实时滚动 |
| `cap digest` | 摘要：接口聚合、耗时、异常 |
| `cap chain` | 按业务链路串联（省→市→区→区域网点→创建运单） |
| `cap chain --full` | 同上，带请求/响应体 |
| `cap grep destinationSite` | 全文搜索，命中处带上下文 |

### 过滤（多数命令通用）

```
--host 8.214.27.92       按主机
--path waybill/create    按路径
--method POST            按方法
--status 200             按状态码
--client 172.17.38.225   按客户端 IP
--since 5m               起始时间：5m / 2h / 30s / 14:30
--grep destinationSite   全文搜索
--last 20                最近 N 条
--all                    包含系统杂音（默认折叠）
--json                   输出 JSON
```

## 两个默认行为，都是为了"看起来干净"

### ① 系统杂音自动折叠

googleapis / miui / apple / 广告 SDK 之类的 CONNECT 默认不显示：

```
$ cap list --last 8
共 8 条（已折叠 60 条系统杂音，--all 可看）
[   29] 16:29:26  GET  8.214.27.92:3000/basic/basicConfig/queryList  → 200 (112ms)
[   88] 17:02:32  GET  8.214.27.92:3000/basic/users/getTime          → 200 (195ms)
```

要看全部：`--all`。要调整名单：改 `capture.py` 里的 `NOISE_HOSTS`。

### ② 敏感头默认脱敏

`authorization` / `cookie` / `token` 等落盘前自动打码（保留前 4 位便于对照）：

```json
"authorization": "2342…<已脱敏>"
```

要抓完整值（临时排查用）：`cap config set redact false`，排查完记得改回来。

## 抓本机流量（等价于 Charles 的 macOS Proxy）

**推荐做法：在「设备」页把「本机（这台 Mac）」那台点绿。** 点绿 = 系统代理接上 + 开始抓，点灰 = 还原 + 停止，一个动作两件事。

命令行等价操作：

```bash
cap local on      # 把系统代理指向 127.0.0.1:8890（会先备份原设置）
cap local         # 看当前状态
cap local off     # 还原系统代理
```

或者在 Web 工作台的**右侧抽屉 → 「本机流量」**里点开关。

> ⚠️ **本机代理开着时，这台电脑上所有 App 的流量都会经过本工具**（浏览器、微信、VS Code，
> 连 AI 助手的 `chat.deepseek.com` 也一样）。所以平时**别让它常开**，只在真要抓本机时点绿。
>
> ✅ **不用怕忘关**：`cap stop` / Ctrl+C / 关掉服务时，本工具会自动把系统代理还原成开启前的样子
> （备份存在 `system-proxy-backup.json`）。
>
> 🛡 **就算被强杀 / 崩溃，也不会断网** —— 有「断网保护」看门狗兜底，见下。

### 🛡 断网保护（看门狗）

系统代理一旦指向本工具，本工具挂掉 = 这台电脑断网。**这是所有抓包代理的通病**
（Charles / Proxyman / mitmproxy 都一样）：它们靠"退出时还原"兜底，但**被强制退出或崩溃时没人兜**。
你可以自己验：把 Charles 强退，这台电脑同样上不了网。

本工具多了一个独立的小看门狗，**每 2 秒**查一次「系统代理是不是指着本工具，而本工具已经不在了」：

```
代理指着 127.0.0.1:8890，但 8890 已经没人监听
        ↓  ≤2 秒
看门狗还原系统代理 ──▶ 网络恢复
```

实测：`kill -9` 强杀代理进程后，**第 4 秒网络自动恢复，全程无需人工干预**。

| 命令 | 作用 |
|---|---|
| `cap guard status` | 看断网保护在不在岗 |
| `cap guard start` | 手动拉起（点绿「本机」时会自动拉起，一般不用敲） |
| `cap guard stop` | 停掉保护（不推荐） |

工作台的**「本机流量」栏**会显示 `🛡 断网保护在岗` 徽标，肉眼可确认。

> 两个配套动作让它闭环：代理重启时若「本机」仍在监听，系统代理会**自动接回**、看门狗**自动重新上岗**；
> 若「本机」已不在监听却还指着本工具（上次崩溃残留），启动时会**自动还原**。

### HTTP 能看全，HTTPS 只看得到域名

| 类型 | 能看到 |
|---|---|
| **HTTP**（如 `http://8.214.27.92:3000`） | ✅ 完整请求头/体、响应头/体 |
| **HTTPS**（如 `https://news.baidu.com`） | ⚠️ 只有 `CONNECT news.baidu.com:443`，**看不到内容** |

实测：

```
[164] GET     www.baidu.com:80/        → 200 (27ms)     ← HTTP，完整抓到
[165] CONNECT news.baidu.com:443                        ← HTTPS，只有隧道
```

Charles 能看到 HTTPS 内容，是因为它做了 **MITM**（你信任过它的根证书）。
本工具要解密 HTTPS 需要同样装一次根证书——目前未做。

### 方式一：`cap devices`（看谁接进来了）

**不需要设备发业务请求也能识别** —— 因为手机连上 WiFi 后一定会做联网探测：

| 探测域名 | 判定 |
|---|---|
| `connect.rom.miui.com` | Android（小米） |
| `connectivitycheck.gstatic.com` | Android |
| `captivitycheck.platform.hicloud.com` | Android（华为） |
| `captive.apple.com` | iOS / macOS |
| `www.msftconnecttest.com` | Windows |

所以刚连上、还没打开 App 的设备，也能认出平台：

```
$ cap devices
  ▸ 172.17.38.225   Android（只看到联网探测，还没发业务请求）
      40 个请求 · 最近 16:47:35

  ▸ 172.17.38.99    Android · Redmi 21091116C        ← 发过业务请求后更精确
      App 1.0.502 · NG · 网点 623 · GMT+01:00
```

识别优先级：**App 请求头 `scan-source`（最精确）→ 联网探测域名 → UA**

### 方式二：`cap scan`（主动扫网段）

不依赖任何流量，直接扫局域网：

```
$ cap scan
  扫描 172.17.38.1 – 172.17.39.254    共 508 个地址    用时 6.4s

  ✅ 已经在走代理（1 台）
      172.17.38.225    Android（只看到联网探测）   40 个请求

  📶 网络上活着、但没走代理（118 台）
      172.17.38.6      58:6c:25:5e:14:5b
      ……

  🌐 ARP 表里的其他设备（共 34 台）
      ……
```

参数：

```bash
cap scan --subnet 172.17.38     # 只扫一个 /24
cap scan --no-ping              # 跳过 ping，只看 ARP 表（秒出）
cap scan --timeout 1.0          # 提高单机 ping 超时
cap scan --json
```

### 方式三：USB 连接的设备

`cap devices` 会顺带列出 USB 上插着的手机，三条来源互为补充：

| 来源 | 能拿到 |
|---|---|
| `idevice_id` / `ideviceinfo`（libimobiledevice） | iOS 设备名、机型、系统版本、UDID |
| `ioreg -p IOUSB` | 所有 USB 设备名（Android 也能看到） |
| `adb devices`（装了 adb 才有） | Android 设备 |

```
  USB 上连接的设备（1 台）
      iOS · 我的 iPhone · iPhone14,3 · iOS 17.4
          UDID 00008110-001A2C3D4E5F6G7H
      → USB 连着的设备不走 Wi-Fi 代理；要抓它的包，得改用 Wi-Fi 代理
```

> USB 插着 ≠ 能抓包。抓包靠的是 Wi-Fi 代理，USB 只是用来**确认设备在不在**。
> 跳过 USB 检查：`cap devices --no-usb`

### 三个状态怎么区分

| 状态 | 含义 |
|---|---|
| ✅ 已经在走代理 | 流量正经过本工具，能直接看请求 |
| 📶 活着但没走代理 | 在网络上，但 Wi-Fi 代理没指向本机 |
| 🌐 ARP 里的其他设备 | 最近和本机有过通信的设备 |

## 抓不到怎么办

先跑 `cap doctor`，它会直接告诉你卡在哪：

## 界面（web.html）

界面是**投影** —— 数据契约（`flows.jsonl` 字段、`since_id` 游标、API）不受它影响，
所以它可以整体重做而不损失任何东西。当前这一版：

| 区域 | 设计 |
|---|---|
| 顶栏 | 品牌 + 🟢实时 + `🎧 监听中 N 台` + 条数；右侧「设备与状态」抽屉开关 |
| 筛选条 | 带标签的分组：范围 / 设备 / 主机 / 方法 / 状态；分段控件做「当前·历史」 |
| 请求列表 | 方法徽章（等宽）+ 主机淡色 + 路径高亮；右侧状态码与时间对齐 |

## AI 助手（内置）

右上角「**AI 助手**」。它不是通用聊天框 —— 它**读你机器的实时状态**：

| 它能看到 | 用途 |
|---|---|
| 设备现场（谁在线、谁在监听、谁没连上） | "手机连不上"这类问题能直接给结论 |
| 最近 50 条调试日志（带标签字典） | 知道卡在哪一环，而不是猜 |
| 数据字典（字段含义/单位/取值） | 分析报文时不会把 `volumeM` 当成字符串 |
| 最近 80 条报文（紧凑行格式） | 能指出"是哪几条、哪个字段" |

### 配置（一分钟）

点开 AI 助手 → 填 API Key。三种方式：

1. **一键填写** —— 扫描本机 **8 个可能存 key 的地方**，**逐个实测，只用能通的**：
   环境变量（`DEEPSEEK_API_KEY` / `OPENAI_API_KEY`）、`~/.zshrc`、`~/.bash_profile`、
   `~/.bashrc`、`~/.profile`、`~/.dsh/settings.yaml`、`~/.deepseek/config.json`

   > 会把你自己的 key 排在前面，失效就自动回退到下一个，并**列出每个 key 的测试结果** ——
   > 不会闷声用一个失效的 key 让你以为配好了。
2. **手动粘贴** —— 选服务商、模型，粘贴 key
3. **拉模型列表** —— 从服务商拉取可用模型，下拉选

内置服务商预设：**DeepSeek / OpenAI / 月之暗面 / 阿里通义 / 自定义**。
底层走 OpenAI 兼容协议，所以任何兼容接口（含本地 Ollama）都能用 —— 换 Base URL 即可。

```
key 存在 credentials.json（权限 0600），不写进 config.json
—— 配置可能被分享、贴出来，凭据不行
```

### 两种模式（自动切换）

| 模式 | 什么时候 | 它的行为 |
|---|---|---|
| **问题诊断** | 问"怎么/为什么/连不上/报错" | 按固定排查顺序给结论 + 下一步动作 |
| **数据分析** | 问"分析/字段/统计" | 只依据数据字典解释字段，字典没有的**明确说不确定** |

对话是**流式**的（SSE 逐字推送），不用干等。回答用 Markdown 渲染。

### 它被明确禁止做的事

- **猜字段含义** —— 字典里没有就说"还没核对过"，并指向 `semantics.json` 的 `pending`
- **泛泛而谈** —— 要求引用具体设备/日志/记录号作为证据

> 实测：问"现在能抓包吗"，它答的是「代理在 8890、系统代理已接管、192.168.0.108（Redmi）在线、
> 最新到 id 1261–1264」—— 带证据，不是套话。

## 三个"地基"文件（数据，不是代码）

界面上的一切都可以重做。**下面这三样不行** —— 它们是实物：

| 文件 | 是什么 | 为什么不能丢 |
|---|---|---|
| `flows.jsonl` | 抓到的全部报文 | 只追加；删了就回不来 |
| `semantics.json` | **数据字典**：字段什么含义、什么单位、接口叫什么、链路什么顺序 | AI 推不出来。报文里只有 `{"areaCode":"NGA00001"}`，"目的网点"这个标签是**人贴上去的** |
| `identity.json` | 数据归属（本机匿名 id） | 没有它，记录无法确认来自同一主体，拼不起来任何东西 |

### `semantics.json`：AI 能不能读懂的开关

**它是一份数据，不是文档。** 界面、CLI、AI 都读同一份，避免"同一个字段两处含义不同"。

```json
"orderType": { "含义": "订单类型", "取值": { "L": "零担" }, "状态": "已核对" },
"unitVolume": { "含义": "体积", "单位": "cm³", "状态": "已核对" }
```

纪律：**没核对过的一律不写**。宁可缺，不可猜 —— 猜错的语义会让 AI 一本正经地给你错结论。
没核对的记在 `pending.items` 里（现在有 3 项）。

```bash
curl "http://127.0.0.1:8891/api/semantics?what=unitVolume"     # 查一个字段
curl "http://127.0.0.1:8891/api/semantics?what=chains"          # 看链路定义
```

业务链路（`录单` / `签收`）也在这里 —— 原先硬编码在 Python 字典里，现在 `cap chain` 读它。

### `identity.json`：每条数据属于谁

首次运行自动生成，权限 `600`：

```json
{ "user_id": "u_dfcb2530935d4f3e", "kind": "anonymous-device" }
```

之后每条记录都带 `user_id`（**只加字段**，原有 15 个字段一个没动）。
早于身份层的历史记录没有这个字段 —— **不去补**，忠实反映当时没有身份层这件事。

编排是"先一台设备一个匿名 id，但结构按一个人可多设备设计"：以后登录绑定账号时，
历史数据自然归属过去，**不需要迁移**。

> 为什么现在就要有：`client` 字段是设备 IP，换 Wi-Fi 就变（这台手机从 `172.17.38.225`
> 变成了 `192.168.0.108`）。IP 是定位符，不是身份证。

## 功能自述：`manifest.json`

这是"以后能把功能打包、下载、替换"的形状模板：

```bash
cap manifest            # 看这个功能是什么、要什么权限、提供什么数据
cap manifest --check    # 校验「声明」和「现实」是否一致
```

`--check` 会真的去探测每个声明的接口、比对端口配置、确认权限声明齐全：

```
✅ 入口文件存在          ✅ 代理端口与 config 一致
✅ 语义文件存在          ✅ 接口可达 /api/flows      HTTP 200
✅ 系统代理权限已声明     ✅ 声明与现实一致
```

**为什么要有这个校验**：声明和现实一定会漂移（改了端口忘了改 manifest、加了接口没登记）。
不靠自觉，靠命令查。

其中 `permissions` 不是装饰 —— 抓包要改**系统代理**（能让你整台电脑断网），
这个能力必须显式写出来，`risk` 和 `mitigation` 也一并声明。以后下载别人的功能时，
用户看的就是这一段。

## 调试日志（trace.log）

开发调试期，每个「判断点和它的结果」都会记一行，**出问题直接读日志，不用截图**：

```bash
cap trace                 # 看最近 60 条
cap trace --last 200      # 看更多
cap trace --grep MON      # 只看某一类
cap trace -f              # 持续跟踪（像 tail -f）
cap trace --clear         # 清空
```

也能从浏览器读：`http://127.0.0.1:8891/api/trace?n=100&grep=MON`

格式固定成 `时间 | 标签 | 事件 | 细节`，一行一条：

```
21:51:04.503 | MON    | 收到切换   | set='127.0.0.1' 客户端=127.0.0.1
21:51:04.504 | MON    | 写入配置   | monitored=['127.0.0.1','192.168.0.108'] 之前=['192.168.0.108']
21:51:05.371 | GUARD  | 上岗      | PID 2293 每 2.0s 查一次
21:51:05.383 | LOCAL  | 接管系统代理 | Wi-Fi → 127.0.0.1:8890 断网保护=PID 2293
21:51:14.657 | PROXY  | 放行      | 来自 192.168.0.108
21:51:18.838 | WEB    | 取请求     | since=1019 文件=1020 增量=0 返回=0 监听=['192.168.0.108']
```

**这张表就是排查路径** —— 手机连不上时，看卡在哪一环：

| 标签 | 记什么 | 没有这一行说明 |
|---|---|---|
| `BOOT` | 启动快照：端口、监听集合、本机 IP、系统代理状态 | 服务没起来 |
| `PROXY` | 放行某个客户端 | 手机根本没连过来（网络/代理没配对） |
| `DROP` | 拒绝某个客户端 + 它属于哪个网段 | **连上了但被网段限制拒了** |
| `DEV` | 发现新设备 / 在线状态翻转 | 设备还没发过任何请求 |
| `MON` | 绿点切换：改了什么、结果如何 | 点击没到服务端（多标签页打架？） |
| `LOCAL` | 系统代理接管 / 还原，含备份的原值 | 本机流量没接上 |
| `GUARD` | 断网保护上岗 / 收工 / 触发 | 保护没运行 |
| `WEB` | 每次取数据：文件多少条 → 过滤后返回多少 | 前端没在拉数据 |
| `PHONE` | 手机打开接入页（含 UA） | 二维码没扫到 / 打不开 |

用 `cap config set debug false` 可以关掉（默认开）。超过 4MB 自动轮转成 `trace.log.1`。

## 数据格式

`flows.jsonl`，**追加式一行一条**：

```json
{
  "id": 88,
  "ts": "2026-09-14T17:02:32.123",
  "kind": "http",
  "method": "GET",
  "host": "8.214.27.92",
  "port": 3000,
  "path": "/basic/users/getTime",
  "url": "http://8.214.27.92:3000/basic/users/getTime",
  "client": "172.17.38.225",
  "noise": false,
  "req_headers": { "...": "..." },
  "req_body": "",
  "status": 200,
  "resp_headers": { "...": "..." },
  "resp_body": "{ ... }",
  "ms": 195
}
```

- `kind`: `http`（完整记录）/ `connect`（HTTPS 透传，只记目标主机）
- `noise`: 是否系统杂音
- 直接 `tail -f flows.jsonl`、`grep`、Python 解析都行

## 已知边界

| 项 | 说明 |
|---|---|
| **HTTPS** | 只透传不解密，记录目标主机。要解密 HTTPS 需加 MITM + 手机装一次证书 |
| **HTTPS 连不上** | 隧道建立失败（域名解析不了 / 端口不通）会直接在对应记录上写明原因，能被「错误」筛选到 |
| **手机联网探测** | 小米 `connect.rom.miui.com/generate_204` 走代理会超时（会记成异常），**不影响业务请求** |
| **请求体压缩** | 支持 gzip 解压后再记录 |
| **单条正文** | 超 40 万字符截断，并标注原始大小 |
| **图片/视频等二进制** | 只记 `<二进制内容 N 字节，未保存>`，不落盘 —— 否则一条 5MB 下载就能让日志涨 1MB |
| **日志轮转** | 超 80MB 自动轮转为 `flows.jsonl.1`（只留一份，最多占 160MB） |
| **日志很大时会变慢** | 每次刷新要解析整个日志：1MB≈22ms、10MB≈180ms、40MB≈740ms。攒太多就 `cap clear` |
| **一个网络一个代理** | 手机指到本工具后 Charles 收不到流量；要切换就改回去 |
| **换 Wi-Fi 后** | 本机 IP 会变，手机的代理地址要跟着改成 `cap status` 里显示的「主机名」 |
| **App 不走系统代理** | 少数 App 自建网络栈会绕过代理，抓不到 |
