# 工作平台

个人工作平台。**常用工具、文件夹、应用和网页的快捷桌面**。点「＋ 添加」把需要的入口放上来，其余功能留在工具库。

```
双击桌面的「工作平台」 → 打开 http://127.0.0.1:8880 → 点卡片打开功能
```

## 数据在哪

```
工作平台/
├── registry.json      哪些功能被注册了（记路径，不强制搬进 features/）
├── identity.json      平台身份 —— 所有功能共用同一个 user_id（权限 600）
├── ai.json            AI 配置（可选；不填就自动复用抓包工具已配好的 key）
├── lib/platform_lib.py  共享能力：AI 调用、身份、key 扫描
├── features/<id>/     功能目录
├── store/<id>/        商店里可安装的功能
├── web/desktop.html   桌面首页
└── platform.py        主机（零第三方依赖）
```

**每个功能自己的数据在自己目录里**，别的功能不许直接读文件 —— 只能走对方
`manifest.json` 里 `exposes` 声明的接口。这样生产者能随时改存储实现，消费者不用跟着改。

## AI 根入口（改不坏的那一层）

平台自带一个 AI 入口，**不在功能列表里** —— 功能全坏了它还在。

```
桌面右上角 ✦ AI 助手          ⌘I 呼出
```

它能做三件事：答技术问题、读日志/报文/代码找问题、**改这个平台自己的代码**。

改代码的规矩（在 `lib/ai_core.py` 里，**AI 自己改不了自己**）：

| 规矩 | 为什么 |
|---|---|
| 改前先备份 | 改错了能回滚 |
| 改完做语法检查，不过就自动回滚 | 不让平台起不来 |
| `platform.py` / `lib/ai_core.py` / `lib/platform_lib.py` / `identity.json` 拒绝修改 | **万一改错了，AI 入口还在，还能救回来** |
| 每次改动写审计记录 | 知道谁在什么时候改了什么 |
| 只能改平台目录内的文件 | 挡住 `../` 越界 |

想换模型/换 key 去「设置」页 —— 那是配置，不动代码。

### AI 值守（主动那一半）

后台每 60 秒看一轮，盯三件事：日志错误扎堆、构建失败、功能 critical 告警。
发现异常就自己分析，结论进「今日关注」（🤖 标记）。

```bash
python3 lib/ai_watch.py --once     # 手动跑一轮
curl -X POST http://127.0.0.1:8880/api/watch/run    # 一样的效果
```

**会自动做的（安全子集）**：功能进程掉线 → 拉起来。同一个功能 10 分钟不重复重启，
一轮最多 3 个，每次写进 `ai_auto.jsonl`。

**只报告不动手的**：改代码、删文件、清构建产物 —— 必须你点头。

**不越界**：同一个问题 30 分钟内只报一次；没配 AI 时静默跳过；
认得"已知被墙的域名"，网络环境问题不算故障（误报比不报更糟）。

点「今日关注」里那条 🤖，AI 的分析会填进对话框 —— 确认一下就能让它接着修。

### 看图

AI 面板点「📷 看截图」，或者 **⌘V 直接粘贴**，或者把图拖进对话框。
截图来源包括：平台暂存的、桌面上的、截图文件夹里的。

```bash
# 命令行也行
curl -X POST http://127.0.0.1:8880/api/ai/vision \
  -H 'Content-Type: application/json' \
  -d '{"paths":["/path/to/shot.png"],"q":"这界面有什么问题"}'
```

**模型要用 `deepseek-flash`** —— 实测它能看图（`deepseek-v4-pro` 不能，
它看到的是 `[Unsupported Image]`）。
`max_tokens` 要给足（默认 3000）：模型先输出思考，给少了 `content` 会是空的。

### 自主模式：给个目标，它自己干完

AI 面板里勾上「自主模式」，它会自己循环：

```
读代码 → 想 → 改 → check_syntax 验证 → 不对再改 → done 汇报
```

一轮只做一个动作，最多 10 轮。做完会汇报**改了哪个文件、第几行、怎么回滚**。

工具清单（它在循环里能调这些）：

| 工具 | 用途 |
|---|---|
| `read_file(rel)` | 读文件（大文件会提示怎么分段读） |
| `read_file(rel, around="关键词")` | **找某个东西在哪** —— 大文件里最常用 |
| `read_file(rel, offset=行, limit=行数)` | 按行区间读 |
| `search(pattern, sub)` | 全平台搜内容 |
| `list_files(sub)` | 列目录 |
| `edit_snippet(rel, find, replace)` | 按片段改（find 必须唯一） |
| `apply_edit(rel, new_text)` | 整文件覆盖（慎用） |
| `check_syntax(rel)` | 验证语法（Python/JSON） |
| `run_command(cmd)` | 跑白名单里的命令（编译/测试/git 只读/本机 curl） |
| `look_at_image(path, q)` | **看一张截图**（App 界面、报错弹窗）—— 模型走 `deepseek-flash` |
| `done(summary)` / `give_up(reason)` | 结束 |

## 上线前先跑健康检查

```bash
python3 healthcheck.py            # 查全部（已装 + 商店副本）
python3 healthcheck.py shotkit    # 查一个
```

查四项：语法能编译、用到的模块都 import 了、manifest id 与目录名一致、
声明的端口在听且界面和 API 都返回 200。

> 为什么需要它：写「上架截图工坊」时漏了 `import urllib.parse` ——
> 进程能起来、端口在听，但**每个请求都崩**，界面返回 000。
> 静态看代码很容易漏，跑一遍就知道。商店里的副本也一起查，
> 这样装之前就知道它能不能跑。

## 加一个新功能

功能必须是这个形状：

```
features/<id>/
├── manifest.json     自述：权限、端口、启停命令、产出数据、对外接口
├── main.py           入口（或 index.html 纯静态）
├── index.html        界面
└── （自己的数据文件）
```

`manifest.json` 的关键段：

```json
{
  "id": "myfeature", "name": "我的功能", "version": "0.1.0", "type": "local",
  "ports": { "web": 8910 },
  "platform": {
    "icon": "🧪", "color": "#2f6df6",
    "open": "http://127.0.0.1:{web}/",
    "health": "http://127.0.0.1:{web}/api/status",
    "start": ["python3", "main.py", "start"],
    "stop":  ["python3", "main.py", "stop"]
  },
  "permissions": [
    { "id": "fs.read.xxx", "why": "为什么要", "risk": "风险", "mitigation": "怎么防" }
  ],
  "data": { "produces": [...], "consumes": [...] }
}
```

放进 `features/` 就自动被发现；放进 `store/` 就会出现在商店里等人安装。

### 四条约定

1. **权限要写清 why / risk / mitigation** —— 抓包的 `system.proxy` 能让你整台电脑断网，
   这种事必须写在明面上，用户下载别人的功能时看的就是这段
2. **数据只追加**，带 `user_id`，能按 id 增量取
3. **字段含义写进自己的 `semantics.json`** —— 没核对过的不要写，宁可缺不可猜
4. **功能之间只走接口**，不读对方文件

> **安装/卸载语义**（踩过坑）：卸载默认**保留文件**（不删用户数据），
> 但 registry 里会记进「已卸载名单」，自动扫描跳过它 ——
> 否则扫描会把目录重新注册回来，卸载等于没卸。
> 再点「安装」= 从名单移除并重新注册（不重新拷贝，免得覆盖你攒的数据）。

> 检验标准：**这个功能删掉，数据还在吗？**
> 在 → 它只是投影，可以随便重做。不在 → 它动了地基，要慎重。

## 平台自己的功能（工作台）

桌面负责快捷打开，工具库负责按需添加，关注事项与 AI 保留在顶栏：

### 1. 今日关注 —— 功能主动汇报

功能实现一个接口，就能让自己的"需要注意的事"出现在首页：

```python
if u.path == "/api/digest":
    return self._send(200, json.dumps({"items": [
        {"level": "critical",              # critical / warn / info
         "title": "「某仓库」卡在变基中",
         "detail": "分支 dev_x　13 处改动",
         "action": "打开仓库总览处理"},
    ]}, ensure_ascii=False))
```

平台每 90 秒并发问一遍所有在跑的功能，汇总排序后收集起来。

「今日关注」保留在顶栏按钮中，点击或按 `⌘D` 打开左侧抽屉。它不占用桌面图标位置。
`Esc`、遮罩和关闭按钮都可以关闭；点击一条关注项即可转到对应功能。

> **硬性要求：digest 必须在 2 秒内返回。**
> 功能各自要扫描（读钥匙串、遍历仓库），现场算动不动十几秒 ——
> 平台等不了，等不到就直接跳过，你的告警就永远不显示。
>
> **正确做法：缓存 + 后台刷新。**
> ```python
> _cache = {"t": 0, "rows": None, "busy": False}
>
> def scan_cached():
>     if _cache["rows"] is not None and time.time() - _cache["t"] < 300:
>         return _cache["rows"]          # 新鲜，直接用
>     if not _cache["busy"]:             # 过期了：后台去刷新
>         _cache["busy"] = True
>         threading.Thread(target=refresh_and_store, daemon=True).start()
>     return _cache["rows"]              # 立刻返回旧值（可能是 None）
> ```
> 第一次调用返回「正在统计…」，之后就是毫秒级。
> 仓库总览按这个改完：**25 秒 → 0.002 秒**。

**别喊狼来了。** 磁盘占用一开始把 iOS 模拟器运行时卷报成「98% 快满了」——
那些是只读镜像，天生就是满的。**误报比不报更糟**，会让人把真的告警也忽略掉。
它现在只报 home 目录所在的那个卷。

### 2. 一个入口添加所有东西

桌面「＋ 添加」里可以：

- **工具**：搜索名称或用途，点「＋ 添加」。尚未安装的工具会从本地工具库安装；已隐藏的直接显示回来。
- **文件与文件夹**：调用系统选择窗口，选好直接添加。macOS 支持一次多选；也可以粘贴完整路径。
- **网页**：粘贴网址，自动识别名称，回车添加。网页标题读取失败时使用域名，不影响添加。
- **应用**：搜索本机应用，点击添加，也可以通过系统窗口选择。

在桌面空白处按 `⌘V` 粘贴网址或路径，会直接进入添加预览。输入框中正常粘贴不会被抢走，AI 的图片粘贴保留原有行为。
系统窗口取消时不添加任何东西；无法调用系统窗口的环境可以使用路径输入。

### 3. 统一管理快捷入口

右键任意图标可打开、编辑名称、调整位置或从桌面移除。
文件、文件夹和应用还可在文件管理器中显示，路径失效时可修改入口。

- **移除只操作桌面入口**：原文件不删除，工具不停止、不卸载。
- 移除后提示条提供 **12 秒撤销**，恢复原名称、图标和位置；服务端撤销凭据有效期为 60 秒，重启服务后失效。
- 工具在桌面上的名称单独保存，不会改动工具的 manifest。
- 桌面隐藏工具可以随时从「添加」或「工具库」加回来。
- 真正卸载仍使用 `POST /api/uninstall`；只有显式传入 `delete: true` 才删除平台 `features/` 下的功能副本。

### 4. 固定排序与快捷打开

拖动图标调整顺序，刷新后保持原位。也可以在图标菜单中「向前移 / 向后移」。
`⌘K` 搜索桌面入口、工具库或设置；图标支持键盘聚焦后回车打开，`F2` 编辑。
点工具时检查服务是否可用，需要时自动启动，启动失败会给出提示。

自定义入口、顺序、隐藏工具和工具别名都存在 `desktop.json` 中。
旧版的注册表和桌面入口继续保留，`prefs.json` 中的最近使用记录也继续记录。

### 5. 设置页

AI、身份、路径都在一个地方配，不用去各功能里翻。**一键填写**会扫本机
可能存 key 的地方，逐个实测，只用能通的，并把每个的结果显示出来。

## 平台提供的共享能力

功能通过 `lib/platform_lib.py` 拿，不用自己实现：

```python
import sys, os
sys.path.insert(0, os.path.join(os.path.dirname(__file__), "..", "..", "lib"))
from platform_lib import ai

for piece in ai.stream([{"role": "user", "content": "..."}]):   # 流式
    print(piece, end="")

ai.ready()        # 有没有配好
ai.user_id()      # 平台统一身份
ai.find_keys()    # 扫本机可能存 key 的地方
```

**AI 是平台能力，不是每个功能各配一遍 key。** 所有功能共用一个 key，
来源优先级：`工作平台/ai.json` → 环境变量 → 抓包工具已配好的 `credentials.json`。

## 已知边界

- 平台只监听 `127.0.0.1`，局域网访问不到（除了抓包的手机接入页 8892，那是刻意的）
- 功能都是**本机本地**的，没有云同步；`identity.json` 已经预留了多设备统一的身份
- 商店是**本地目录**（`store/`），没有远程仓库；要分享就把目录拷给别人
- 平台自己没有守护进程，功能进程由各自的 `start` 命令拉起；平台退出不会停掉它们
